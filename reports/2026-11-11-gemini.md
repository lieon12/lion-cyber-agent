# Laporan Lab Gemini — 2026-11-11

Target: https://www.verifydeal.site/ (website sendiri, pengujian)
Otak: Gemini gemini-3.8-flash via custom.gemini (kunci tersimpan aman, tidak ada di repo)
Tools dipakai: check_site_basic, fetch_url, scan_sql

## Yang berhasil

- Koneksi Gemini terhubung dan panggilan pertama berhasil.
- Gemini merencanakan dengan benar: `{"tool": "check_site_basic", "args": {"url": "https://www.verifydeal.site/"}}`
- Validator menyetujui tool itu (domain diizinkan, payload aman).
- Tool dijalankan dan hasilnya benar.

## Temuan

- check_site_basic: status 200
  * Memakai HTTPS.
  * Tidak ada header Content-Security-Policy (CSP).
  * Tidak ada header X-Frame-Options — rentan clickjacking.
  * Tidak ada header X-Content-Type-Options.
- fetch_url: Pusat Laporan Identitas Digital (status 200, server Vercel)
- scan_sql: https://www.verifydeal.site/ param=q (baseline status 200)
  * Tidak ada sinyal kuat. Bukan berarti 100% aman — lanjutkan audit kode.

## Yang gagal (sementara, dari Google)

- Panggilan Gemini ke-2 dan ke-3 mengembalikan HTTP 503 UNAVAILABLE:
  "This model is currently experiencing high demand. Spikes in demand are
  usually temporary. Please try again later."
- Ini bukan salah kunci atau kode — Google sedang penuh. Lab jatuh kembali
  ke mode rule-based untuk menyelesaikan scan, dan semua tool tetap jalan.

## Catatan

- Scan memakai payload non-destruktif saja.
- Data di laporan ini adalah bahan untuk melatih model sendiri nanti.
